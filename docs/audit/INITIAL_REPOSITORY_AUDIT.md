Scope: every tracked first-party source, contract test/helper, frontend integration, build/dependency configuration, public deployment record and documentation. ## PRD differences and security-relevant gaps

| Gap | P0 consequence |
| --- | --- |
| Direct manual `resolve` is final (`QiePredictionMarket.sol:238`) | Replace for new deployments with proposal/challenge/arbitration; preserve legacy behavior under its original address. No exploitable fund-seizure bug established by this review. |
| No activation or pause gate (`:183`, `:205`) | Legacy is Testnet-only; it must never be used as the production contract. New payable activity must fail closed until explicit approvals and activation. |
| No bonds, fees, or role configuration (`:160`) | Add isolated participant, fee and three bond ledgers; snapshot future-market configuration. |
| Plain on-chain strings; no metadata content commitment (`:114`, `:195`) | New market metadata hash and content-addressed URI must be immutable. Off-chain availability remains a separate requirement. |
| Rounding dust permanently held (`:31`) | Preserve entitlements; no new sweep until product policy is approved. |
| No dispute/activation/fee/bond tests | Add boundary, authorization, multi-market conservation, failed-transfer and stateful action coverage for new protocol. |
| Frontend is hardwired to Testnet/manual ABI (`frontend/src/constants.ts:3`, `config.ts:29`, `chain.ts:22`, `:330`) | New ABI is a breaking migration; leave current UI and public manifest untouched during P0. |
| No operational backend/indexer or launch eligibility enforcement | P0 contracts alone do not complete the PRD or authorize a financial launch. |

No claim of exhaustive vulnerability discovery is made. Existing invariants do not cover nonexistent bond/fee/dispute ledgers. Legacy UI reads outside global verification are separate latest-state requests (`frontend/src/chain.ts:99`, `:166`); a future adapter should use consistent blocks for previews and never treat an estimate as a guaranteed return.

## Planned modular boundary and breaking changes

Before code changes: keep the legacy deployment intact. Implement `MarketFactory` as the new deployable facade inheriting audited-at-source `MarketResolver` and `PredictionPool` modules over a shared internal ledger. A separate noncustodial `ProtocolConfig` owns governance, guardian, approval and future-market parameters. This avoids payable cross-contract bond forwarding, mutable module wiring and duplicated solvency calculations. No proxy, delegatecall or upgrade mechanism is planned.

New functions, events, structs, result lifecycle, content commitments, payable creation/bonds and configuration identity cannot be used with the legacy ABI. Detailed migration instructions belong in `docs/migration/FRONTEND_ABI_MIGRATION.md`. Production network parameters will be independently checked; no Mainnet broadcast, deployment, activation, push or pull request is authorized by this task.
