# ORAKL v1 — baseline source and test review

Baseline: `security/orakl-p0-3` at `9e256c1451d666889f9f248edee3e2e2d61f6d48`; target is QIE EVM Mainnet. This is a first-party review, not an independent audit. Financial activation, deployment and signing remain outside scope. No new production code is justified solely by the findings below. The existing PRD remains the product target, not evidence that the target is implemented.

## Existing test inventory and review boundaries

- `contracts/test/unit/` exercises creation, immutable snapshots, release authorization, configurable bounds, resolution, pool and bond/receiver paths; `contracts/test/integration/Lifecycle.t.sol` covers concurrent markets.
- `contracts/test/fuzz/Accounting.t.sol` exercises payout ordering, rounding, caller/deadline boundaries and variable participant cases. `contracts/test/invariant/OraklInvariant.t.sol` uses handler and ghost state for A–P; its model uses eight actors and caps market creation at 24 ([handler](../../contracts/test/invariant/OraklInvariant.t.sol#L147)). Fixed scenario bounds, skipped actions and modeled mock controls limit the claims of these campaigns.
- `contracts/test/security/` exercises P0.3 admission, independent fixed-size evidence, timestamp boundaries, pause and adversarial role execution. `contracts/test/remediation/` covers emergency release, role drift, caller ownership, callback and legacy transfer paths. `contracts/test/economics/` includes explicit residual demonstrations; a successful residual test is **not** a fix.
- Legacy unit/invariant tests, local helper contracts and mocks remain present. Mocks and cheatcode-pranked caller addresses do not establish production Safe signer authorization, actual QIE RPC finality, real source authenticity or operational evidence handling.

Prior P0.3 command output and exact settings are preserved in [P0.3 verification](../testing/P0_3_VERIFICATION_REPORT.md). This initial review does not claim a new test execution. Fresh release-candidate command results belong in [release verification](../testing/ORAKL_V1_FREEZE_CANDIDATE_VERIFICATION.md). Local test activation fixtures are simulations, not authorization to activate real financial functionality.

## Further independent review

The new evidence profile and URI retrieval require adversarial parser, canonical-encoding, source-authentication, retention and reorg tests before P1; an on-chain hash does not prove contents or consideration. Audit must independently inspect all transfer paths, callback behaviors, arithmetic and rounding dust, actual configuration/wallet code, current role drift assumptions and deployment bytecode with final owner-approved terms. Network compatibility, independently reviewed arbitration, evidence operations and legal authorization remain release gates. No claim of newly discovered exploitation or a fixed defect is made without a failing-before executable reproduction.
