All ten external withdrawal entries use the same storage-based OZ ReentrancyGuard within their respective deployed contract. Legacy nonpayable createMarket has no guard; a payout callback can create a separate metadata-only market, but its monotonically new ID cannot alias the existing market/position and it does not change escrow. Legacy stake/resolve/cancel/withdrawal financial paths remain guarded; this historical source is preserved. v1's six withdrawal entries share one guard across the inherited facade, including transitions. No function accepts an external `account` argument to redirect someone else's entitlement. Internal send helpers have no callable external selector. Every source call site is included above; the new helper is invoked only by `_settle`, `claimBond`, and `withdrawProtocolFees`. The legacy helper is invoked only by `_claim` and `_refund`.

## Incoming value, reclassification and forced credits

- `MarketFactory.createMarket:25` accepts exactly creationBond after active/unpaused/bound-chain/control validation. `_depositBond:117` records creator/amount, increments bondLiability/totalBondsDeposited and emits ownership. Market IDs prevent reuse.
- `MarketResolver.proposeResult:23` accepts exactly proposalBond once after timing, nonzero evidence, caller and current-market checks; records proposer-owned PROPOSAL bond. `challengeResult:49` does the same for one independent challenger-owned CHALLENGE bond before the fixed deadline.
- `PredictionPool.predict:14` records all msg.value as caller's YES/NO contribution; positive snapshotted minimum and remaining uint128 cap prevent narrowing overflow. It increments participantLiability/totalContributions, never bonds/fees. Old-epoch markets reject before mutation.
- These four payable entries fail closed even for zero-value bonds before activation or during pause. ProtocolConfig has no payable acceptance method. Facade receive/fallback reject plain/unknown-selector transfers.
- `_allocateSettlement:94` charges only valid nonempty winners using bounded feeBps. It reclassifies exactly fee from participantLiability to feeLiability and freezes distributablePool. No native send occurs; aggregate accounted liability is unchanged. State guards prevent a second allocation. INVALID, ordinary/emergency timeout and empty-winning-side refunds charge no fee.
- Forced native credits and pre-funded future deployment addresses cannot be prevented by receive guards. Accounting derives from accepted msg.value only; surplus is balance − accounted. Pool denominators, bonds and fees never use raw balance; there is no surplus sweep. No constructor-funded pool path exists.

## Reentrancy, grief and cross-contract state

Every outgoing native call follows authorization → fixed entitlement → CEI → checked transfer → event. Zero v1 amounts skip the callback. Reentrancy into another withdrawal, prediction or resolver transition meets the shared facade guard. A receiver can call the separate configuration contract, but it cannot alter already-terminal user entitlements or the amount debited; legitimate emergency actions may quarantine other markets, not redirect their funds. A gas-burning/rejecting recipient can deny its own payment, with complete transaction rollback; pull payment and owner-directed redirection preserve other users' exits. Reverting wallet views may block new activity, fee collection or arbitration, but participant/refund/bond claims do not query wallet views.

## Executable evidence and disposition of both High reports

`contracts/test/remediation/ValueFlow.t.sol` adds contract-owned redirected withdrawal for all three bond categories with rejected-transfer flag/liability rollback, split fee withdrawal with two markets and forced surplus, missing public-helper/cross-owner rejection, and zero-bond callback isolation. `LegacyValueFlow.t.sol` verifies caller-only payout/refund ownership and cross-market conservation without editing legacy source or tests. Existing `BondsAndTransfers.t.sol` exercises native reentrancy across claim/refund/bond/fee and failed payout/refund/fee transfers. Invariants A–J independently reconcile each liability/withdrawal category; the new rejecting stateful actor attempts failing claims before redirection.

Both Slither High classifications are retained in the analyzer report. **No reachable unauthorized native send was found through the complete current call graph under the declared role trust assumptions.** That is a bounded review conclusion supported by explicit entitlements, recipient checks, CEI, shared guard, caps and regression evidence; it is not a blanket assertion that a helper is harmless. Dishonest real-world arbitration, malicious admitted wallet execution and privileged emergency abort remain separate conditional risks. Any future helper caller or change to accounting requires re-review.
