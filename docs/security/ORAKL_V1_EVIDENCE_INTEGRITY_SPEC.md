# Evidence integrity profile v1 — deterministic candidate, not approved

This is a proposed off-chain convention for P1/indexers; it does not alter [submitEvidence](../../contracts/src/MarketResolver.sol#L27), proposal/challenge, or arbitrator ABI. Solidity accepts any nonzero `bytes32`; it neither enforces this profile nor proves publication, authenticity or consideration. Existing evidence may follow other formats. The operator must approve a final schema and retention policy before freeze.

## Encoding and commitment

The manifest is an RFC 8785 JSON Canonicalization Scheme (JCS) object encoded UTF-8 with no BOM or trailing newline, then `evidenceHash = keccak256(exact manifest bytes)` (Ethereum Keccak-256, **not** NIST SHA3-256). Reject duplicate object keys and invalid UTF-8 before canonicalization. The profile disallows JSON numeric types: `chainId`, `marketId`, `publishedAt` are unsigned base-10 strings, `0` or no leading zero, within uint256; `publishedAt` is claimed Unix seconds and is not authenticated time. Addresses use lowercase `0x` plus 40 hexadecimal digits; content hashes use lowercase `0x` plus 64 hexadecimal digits. Version is the literal `orakl-evidence-v1`.

Required exact fields: `schema`, `chainId`, `contract`, `marketId`, `kind` (`proposal`, `objection`, `supplement`, `decision`), `claim` (`YES`, `NO`, `INVALID`), `proposedOutcome` (`YES`, `NO`, `INVALID`, `NONE`), `sources` (ordered array of source URI strings), `publishedAt`, `publisher` (declared address), `contentHash` (Keccak-256 of exact raw content bytes), `contentMediaType` (ASCII media type), and `media` (ordered array of URI strings, empty allowed). Unknown fields are rejected in this v1 profile; use a new schema version for extension. Arrays preserve order; no Unicode normalization or URI rewriting occurs. URI bytes must be valid UTF-8 and accepted only under a documented safe scheme and length policy; array length and document limits must be set by P1 operators before activation. `contentHash` is independent of a CID and includes every byte including any newline. Each supporting-media URI is a reference; the current v1 profile does not commit separate raw media hashes, so authenticated media requires content-addressed references or a later reviewed version.

Market identity is `(chainId, contract, marketId)`; compare it against the canonical event's emitting facade and chain. The event contributor and the declared publisher may differ. An event proves who submitted a commitment, not that the declared publisher authored it; an independent signature/provenance process must be specified separately. Proposal/challenge/decision records commit their respective supplied hash in existing events/state; evidence-only submissions do not create a bonded objection or grant any claim or authority. A `supplement`/`objection` must explicitly include the proposed outcome; readers must additionally bind to the specific proposal event when multiple proposals or reorgs are possible.

## Retrieval and validation

- A nonzero commitment cannot reveal its URI. Publishers must distribute manifest and content locators through an independently reviewed discovery channel; pin manifest and raw content redundantly and publish retention/availability monitoring. Do not claim `submitEvidence` itself contains a locator.
- If using IPFS, validate the CID using its specified multicodec/multihash against the retrieved representation; a CID is **not** interchangeable with this Keccak manifest hash or necessarily the hash of raw file bytes (UnixFS can wrap/chunk data). Verify the exact raw content bytes separately against `contentHash` and the canonical manifest against the event hash.
- Track independent states: `COMMITMENT_RECORDED`, `CONTENT_AVAILABLE`, `HASH_VERIFIED`, `SOURCE_AUTHENTICATED`, `CLAIM_EVALUATED`. A hash match does not authenticate the source or prove the claim. Unavailable content, bad hash, missing provenance or conflicting records stay visible with reasons and must never silently become verified.
- Each indexer projection must include `availabilityStatus` (`UNKNOWN`, `AVAILABLE`, `UNAVAILABLE`) and `verificationStatus` (`UNVERIFIED`, `HASH_VERIFIED`, `HASH_MISMATCH`, `SOURCE_AUTHENTICATED`, `CLAIM_EVALUATED`), plus observer, observation time and reason; retain underlying checks separately because these statuses are not a total ordering. They are mutable observations external to the immutable manifest and must never be presented as publisher assertions or consensus facts.
- Preserve each log including duplicate commitments. Identity is `(chainId, contract, blockHash, txHash, logIndex)`; reconcile canonical block hashes, rollback reorged entries and replay from persisted checkpoints, separating pending from sufficiently confirmed. QIE confirmation depth and log coverage remain unverified. Index streams/pagination and independent submissions through D, even after formal challenge and during a pause.
- Render source links and media as untrusted input: allowlist schemes, escape text, block executable HTML/scripts and unsafe redirects/SSRF, sandbox media and apply content/size limits. Availability checks must not mutate financial state. The arbitrator's duty to consider material evidence is operational, not enforceable by an event.

## Reproducible test vectors

Run `python3 scripts/check-orakl-evidence-v1-vectors.py` from repository root. Fixtures use fictitious chain `0`, synthetic addresses, and an unresolvable example domain; they are not network configuration. The script verifies exact canonical UTF-8 bytes and Keccak commitments with the installed Foundry `cast`. Two vectors cover an empty content byte string and the ASCII bytes `YES`. This small restricted fixture is not a complete JCS implementation or production parser; independent JCS conformance, Unicode, malicious JSON, provenance and integration tests are required before P1 release.
