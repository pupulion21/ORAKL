All production Solidity and compiler settings remain unchanged. Current bond policy is full return. ## Threat assumptions and findings

An attacker may control multiple funded wallets, both sides of a pool, proposer/challenger slots, transaction ordering and several correlated markets. Honest observers may be offline, undercapitalized or censored. Privileged-role compromise, lying multisig getters, module bypass and arbitration bias are separate assumptions, not permissionless theft demonstrations. The contract commits answers/evidence hashes; it cannot observe real-world truth. Off-chain hedges/bribes can exceed deposited native value.

## Reproducible model and trade-offs

Run `python3 scripts/model-orakl-p0-2-economics.py --output docs/testing/p0-2/economic-model.json`. It uses exact integer payouts and rational probabilities, checks all nine candidate proposal/decision cases, all combinations of zero/positive P/C, cancellation neutrality and hand-computed payout examples. Its candidate policy is **analysis code only**, never called by Solidity or a deployment script. It cannot certify monitoring probability or estimate real gas/QIE price.

The 1,000-unit pool scenarios show: tiny false-winner receipts980; converting a 400-unit losing position to INVALID gains400 relative to truthful YES; one-sided fee escape gains20; a both-sided coalition's payout depends on both owned balances; empty winners refund regardless of the absence of a fee. Recompute position gains for every coalition and correlated market before applying any isolated-proposer expected-value formula. Current full-return principals cannot make detected dishonest proposals intrinsically loss-making before gas/opportunity costs.

Under the candidate, an independent successful challenger wins P and an unsuccessful one loses C. Greater C raises honest monitor funding requirements. A colluding proposer/challenger cannot mint rewards (P+C is conserved) but can bypass a coalition-level punishment and occupy the only slot. Slashing a challenged proposal immediately would let the attacker steal a legitimate proposer's bond; no such rule is recommended. Neutral INVALID/timeout protects good-faith ambiguity/unavailability, while making cancellation a refund strategy. A correct-but-different binary decision and genuine misconduct are not synonymous.

Arbitrator misconduct cannot be determined by asking the same arbitrator whether it misbehaved. Performance bonds/appeals require independent decision authority, pre-finality deadlines, failure fallback and funding rules. No fourth bond category, post-finality reversal or admin fund seizure is introduced. Native asset volatility changes monitor affordability even if P/Tcap is fixed; external bribes are not bounded by pool accounting.

## Independent accounting and transfer review

All production outgoing paths remain the graph audited in [P0.1 value-flow review](../audit/P0_1_VALUE_FLOW_REVIEW.md): participant claim/refund wrappers → owner position entitlement → `_settle` → checked `_send`; `claimBond` → owner bond record → checked `_send`; governance-only fee withdrawal → live declared-control check → accrued fee entitlement → checked `_send`. Each mutating transfer path shares the nonreentrancy guard, reduces only its liability class before transfer, validates destination, and rolls back the whole transaction on a failed send. There is no generic external `_send`, unclaimed-fund sweep, punitive selector, participant loop, retroactive fee change or admin bond recipient choice.

P0.2 adds boundary tests for the uint128 total cap and same-wallet contributions to both sides, all nine disputed outcomes, smallest-unit residuals across resolved/refundable markets, all nine parameter snapshots and separate evidence commitments, a reverting arbitrator with timeout/withdrawal exits, failed bond transfer followed by cross-market reentrancy, and ordinary/emergency cancellation ordering. Existing tests retain forced native surplus and full rollback checks. New invariants M/N independently reconcile immutable terms/evidence, quoted unsettled entitlements, per-wallet floor residuals and global participant reserves, in addition to A–L and the legacy invariants.

Review did not establish a new authorization/solvency bug requiring production Solidity modification. The safe engineering changes are stronger executable evidence, offline scenario tools, exact interface/artifact verification and explicit specification of remaining decisions. Both native-send Slither High detector reports remain visible for independent review; detector labels are not dismissed by inspecting the send helper alone.
